# Liquibase Changelog Conventions

## File Structure

```
src/main/resources/db/
├── changelog-master.yaml          # Includes all changelogs in order
└── changelog/
    ├── 000-create-<table>.yaml    # Table + sequence creation
    ├── 001-hash-trigger-<table>.yaml  # Hash trigger (only if table has image columns)
    └── ...
```

## Master File

`db/changelog-master.yaml` — flat list of includes, ordered by number then table:

```yaml
databaseChangeLog:
  - include:
      file: db/changelog/000-create-<table>.yaml
  - include:
      file: db/changelog/001-hash-trigger-<table>.yaml
```

## Naming

- Pattern: `NNN-description.yaml`
- `NNN` = sequence number (000 for table creation, 001 for triggers, 002+ for migrations)
- Description: `create-<table>` or `hash-trigger-<table>` or a short action description
- The changeset `id` matches the filename without extension (e.g., `000-create-ciafo`)

## Changeset Template — Table Creation

```yaml
databaseChangeLog:
  - changeSet:
      id: 000-create-<table>
      author: services
      comment: Creates the <table> table for <client> <purpose>
      changes:
        - sql:
            sql: |
              CREATE SEQUENCE IF NOT EXISTS <table>_seq START WITH 1 INCREMENT BY 50;
              CREATE TABLE IF NOT EXISTS <table> (
                id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                <columns>
              );
```

## Changeset Template — Hash Trigger

Only for tables with image columns (used by `cache.py` to detect changes):

```yaml
databaseChangeLog:
  - changeSet:
      id: 001-<table>-hash-trigger
      author: services
      comment: Creates function and trigger to auto-compute hash on <table> image columns
      changes:
        - sql:
            splitStatements: false
            sql: |
              CREATE OR REPLACE FUNCTION compute_<table>_hash() RETURNS TRIGGER AS $$
              BEGIN
                NEW.hash = encode(sha256(convert_to(
                  COALESCE(NEW.<image_col1>, '') ||
                  COALESCE(NEW.<image_col2>, ''), 'UTF8')), 'hex');
                RETURN NEW;
              END;
              $$ LANGUAGE plpgsql;

              CREATE OR REPLACE TRIGGER <table>_hash_trigger
              BEFORE INSERT OR UPDATE ON <table>
              FOR EACH ROW EXECUTE FUNCTION compute_<table>_hash();
```

## Rules

- Author is always `services`
- All SQL is raw PostgreSQL — no Liquibase types, no `createTable`, no abstractions
- Use `splitStatements: false` when a changeset contains multiple dependent statements (functions + triggers)
- Every table gets a sequence: `<table>_seq START WITH 1 INCREMENT BY 50`
- Primary key: `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- Only tables with image columns get a `hash` column and hash trigger
- The hash trigger concatenates all image and thumbnail columns with `COALESCE(..., '')`

## Column Types

| Use case | Type |
|----------|------|
| Short text (names, categories, links) | `VARCHAR(255)` |
| Large content (base64 images) | `TEXT` |
| Flags | `BOOLEAN` |
| Hash column | `VARCHAR(255)` |
| Primary key | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |

## When to Add a Hash Trigger

A table needs a hash trigger if and only if:
- It has `TEXT` columns storing base64-encoded images
- Those images are synced to disk by `cache.py`

Tables without images (e.g., `peeps`, `callback`) do not get hash triggers.
